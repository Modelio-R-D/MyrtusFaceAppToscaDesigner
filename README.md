# MYRTUS Face Application: TOSCA Designer Model

A [Modelio](https://www.modelio.org/) project that models the **MYRTUS Face Application** as a TOSCA service template, using the **ToscaDesigner** Modelio module.

The project describes the application topology (software components, hosts, requirements, capabilities and deployment artifacts) with TOSCA node types defined in the `example.eu.myrtus.nodetypes` package.

## Modelled elements

The model fragment `MYRTUS Face Application` contains the following.

**TOSCA node types** (package `example.eu.myrtus.nodetypes`):

- `MyrtusSWComponent`: base software component type, built on `tosca.nodes.SoftwareComponent`.
- `MyrtusCameraFeed`: camera feed service (web service interface `CameraFeed.WebService`).
- `MyrtusFaceDetectionService`: face detection service.
- `MyrtusProxy`: proxy service (web service interface `MyrtusProxy.WebService`).
- `Myrtus-Workstation`: workstation host, built on `tosca.nodes.Compute`.
- `FaceApplication`: the top-level application type.

**Service template** (`MYRTUS_FaceApplication`):

- Node templates instantiating the types above (for example `Myrtus_Proxy_0`, `Myrtus_Workstation_1`, `MyrtusCameraFeed_0`, `MyrtusFaceDetectionService_0`).
- Requirements, capabilities, `host`, `connects` and `egress` relationships between nodes.
- Deployment artifacts such as `nginx.conf`, `fullchain.pem` and `key`.

**Diagrams:**

- `ToscaModelDiagram`
- `ServiceTemplateDiagram`
- `Topology Template Diagram`

## Getting started

1. Clone the repository:

   ```bash
   git clone https://github.com/Modelio-R-D/MyrtusFaceAppToscaDesigner.git
   ```

2. Install the ToscaDesigner module (0.5.02) in Modelio through the module catalog or from a local `.jmdac` file.
3. In Modelio, choose **File > Open a project** and select the cloned folder (the one containing `project.conf`).
4. If Modelio reports that a module or library cannot be found at its original path, point it to your local copy of ToscaDesigner 0.5.02 and activate the module.
5. Open the diagrams from the model explorer.

## Notes

- `project.conf` is generated by Modelio and should not be edited by hand. It contains absolute Windows paths from the machine where the project was created; Modelio resolves them again when the project is opened on another machine.
- Files in `.runtime/` and the index files in `data/` are regenerated by Modelio.
- The model files (`.exml`) are Modelio's own XML format and are meant to be edited from within Modelio.
